## v0.1 — 毎日使える状態（完了。実際の端末での通し確認は継続中）

**1. 設定とパス（完了）**

`Config` 構造体と `Default` 実装。`figment` による階層的な TOML 読み込み。
`notes_dir` を `--dir` / `PEN_DIR` / 設定ファイル / `~/notes` の順で解決。
`pen config path|init|check`。

完了条件: `pen config init` がすべての既定値を出力し、かつコード中の他の
どこにも既定値が書かれていないこと。

**2. 追記（完了）**

`pen <text>` と `pen -`（標準入力）。ディレクトリを必要に応じて作成。
マージ期間つきの時刻見出し。排他ファイルロック。

`clap` の `trailing_var_arg` を有効にして、クォートなしの日本語が通るようにする。
シェルのメタ文字（`&` `|` `>`）はアプリに届く前にシェルが処理するので、
これは防げない。ヘルプに書いて対処する。

完了条件: 1週間の実使用でファイルが壊れないこと（実装・自動テストは完了。
実使用での確認はこれから）。

`config` サブコマンドとメモ本文の衝突が実装時に判明した。`config` を
リネームはせず、`pen -- <text>` のエスケープハッチで対応した
（`.claude/skills/add-subcommand/SKILL.md` 記載の回避策）。

`-t`/`--todo`（完了）。`pen -t "buy milk"` は `pen "- [ ] buy milk"` の
短縮形。テキストが既に `- [` で始まっていれば二重に付けない。

**3. 開く（完了）**

引数なしの `pen` が今日のファイルを `$EDITOR` で開く。未設定なら `vi`。

特定の日を開く形は、実装時に `pen open <date>` サブコマンドに変更した
（当初案の `pen 2026-08-29` は自由テキスト追記と衝突し、`config` の
ときと違って `--` エスケープも効かないため）。`pen open` は日付省略で
今日を開く。ノート本体は開く前には作らず、親ディレクトリだけ用意する
（何も書かず終了したときに空の `.md` が残らないように）。

**4. カレンダー（実装済み・実機での操作確認待ち）**

`pen cal`。月グリッド(日曜始まり)、日ごとのメモ量の濃淡(ファイル
バイトサイズを3段階の背景色にマッピング。固定RGBではなく端末のANSIパレット
に寄せているので、濃淡の段階数はANSIの制約で2階調が上限)、プレビューペイン、
`hjkl`/矢印移動、Enter で開く。`src/action.rs` の `Action` enum を経由する。

端末幅が 100 桁未満ならプレビューペインを落としてグリッドのみ表示する。

Enter で開くときは、raw mode/代替スクリーンのままだとエディタの表示が
壊れるため、`ratatui::try_restore()` で端末を戻してから `$EDITOR` を
起動し、閉じたら `try_init()` でカレンダーに戻る(`pen open` と
同じ `notes::open_in_editor` を共有)。

開発環境に実 TTY が無く、対話操作(移動・濃淡・レスポンシブ・Enter からの
戻り)は自動テストと `TestBackend` での描画アサートまでしか確認できて
いない。実際の端末での動作確認が必要。

**5. 検索(完了)**

`pen search <query>` とカレンダー内の `/`。`grep` クレート(ripgrep の
内部エンジン)は公式ドキュメント自身が「高レベルのガイドがまだ無い」と
明記しており、この規模(1日1ファイル、数百バイト〜数KB)には過大な投資と
判断し、`ignore::WalkBuilder` でツリーを歩いて `regex` クレートで行ごとに
照合する自前実装にした。クエリは大文字小文字を区別しない正規表現として
扱う(grep/ripgrep と同じ感覚)。

カレンダー内の `/` は「入力→Enter→最初の1件にジャンプ」ではなく、結果
一覧を表示して `j`/`k` で選び Enter でジャンプする形にした。

ベクトルインデックスは作っていない。v0.2 の `pen mcp` の
`search_notes` はこの実装をそのまま呼ぶ想定。DESIGN.md の「MCPサーバは
利便性であって本質ではない」「遅さを実測するまでSQLiteを入れない」という
方針に従い、意味検索が必要になったと実際に分かってから検討する。

遅さを実測するまで SQLite を入れない。入れる段階になったら trigram または
bigram のトークナイズが必須になる。FTS5 の既定トークナイザは日本語の1行を
まるごと1トークンとして扱うため、検索がまったく効かない。

## v0.2 — 差別化要素(完了)

- `pen mcp`(完了)。MCP サーバ(stdio)。`search_notes`/`read_note`/
  `append_note` を公開。`rmcp` を使う。既存の `notes::search`/
  `notes::append`/`notes::read_note` をそのまま呼ぶ薄いラッパー。
  非同期が要るのはこのコマンドだけなので `main()` 全体は async に
  せず、`run_mcp` の中だけで tokio ランタイムを組み立てて `block_on`
  する。実際に MCP の `initialize`/`tools/list`/`tools/call` を
  JSON-RPC で送って疎通確認済み。
- `pen context --since 7d --max-tokens N`(完了)。直近のメモを
- `pen context --since 7d --max-tokens N`(完了)。直近のメモを
  LLM に渡す形で出力。`--since` は `7d`/`2w` のような日/週指定
  (ノートは1日1ファイルなので時間単位は意味を持たない)。トークン数は
  文字数ベースの簡易推定(1トークン≒2文字、日本語混在を想定して安全側)。
  正確なトークナイザ(`tiktoken-rs` 等)は追加しない——特定モデル向けの
  精度を追っても他のモデルではどのみちずれるため。新しい日から遡り、
  予算を超える手前で日単位に打ち切る(ファイルの途中では切らない)。
  直近1日だけで予算超過でもその1日は返す。
- 前日の未完了 `- [ ]` を今日に繰り越す(完了)。今日のファイルを
  (`pen <text>` でも `pen open`/カレンダーの Enter でも)初めて
  作る瞬間だけ発動する。「前日」ではなく直近にファイルがある日まで遡る
  (最大365日)。繰り越し元のファイルは変更しない——見つからなければ
  次にファイルを作るときにまた同じ項目が対象になるので、書かずに終了
  しても取りこぼさない。繰り越した項目の直前には
  `<!-- carried over from YYYY-MM-DD -->` を1行添えて、元は何日のノート
  かが分かるようにする(`pen context` の `<!-- estimated tokens: ... -->`
  と同じ、ツールが挿入したメタ情報である旨を示す記法)。時刻見出し
  (`## HH:MM`)は繰り越し項目より後、実際に今日書いた内容の直前に置く
  ——繰り越しは今日書いたものではないので見出しの対象に含めず、見た目の
  区切りにもする。

`全コマンドへの --json` は元々ここに書いていたが、
`.claude/skills/add-subcommand/SKILL.md` が「任意ではない」と明記しているため
v0.1 ステップ1・2で前倒しして実施した。新しいコマンドを追加するときは
最初から `--json` を付けること。

## v0.3 — キーバインドの設定対応(完了)

`[keys.calendar]`/`[keys.search_input]`/`[keys.search_results]` でアクション
ごとにキーを上書きできる。既定値は `action.rs` のモードごとの表が唯一の
情報源(`Config::default()` はそれを呼ぶだけ)。`src/keys.rs` がケバブ小文字の
キー仕様(`h`、`ctrl-a`、`enter` など)をパースする。

存在しないキー仕様、または同じモード内で2つのアクションが同じキーを取り合う
場合は `pen cal` 起動時にエラーにする(黙って上書きされると再現できないバグ
報告になるため)。`[keys.*]` の中のアクション名のタイポは
`warn_unknown_keys` が再帰的に検出して警告する(起動は止めない、既存の
未知キー警告と同じ扱い)。
