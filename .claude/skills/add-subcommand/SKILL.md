# サブコマンド・アクションの追加

順序に意味がある。特に最初の名前の確認を飛ばすと被害が大きい。サブコマンド名は
このツールの中核機能と衝突するため。

## 1. メモ本文との衝突を確認する

`pen <text>` は自由テキストを追記する。サブコマンド名は、利用者がメモの
書き出しに使えなくなる語である。

```sh
pen cal を予約した      # メモではなくカレンダーが開く
```

追加前に問うこと。

- 日本語のメモの書き出しに来にくい短い英単語か → よい
- ありふれた英単語か → よくない。英語でメモを書く人もいる
- 既存コマンドのフラグにできないか → できるならそちらを優先

サブコマンドの総数は少なく保つ。追加のたびに、利用者が打てる文字列が永久に
狭まる。名前が正当化できる場合は、ヘルプに `pen -- <text>` という
回避手段を明記すること。

## 2. clap に配線する

`src/cli.rs` にバリアントを追加する。既定の追記パスの `trailing_var_arg` の
挙動を壊していないか、変更後に必ず確認すること。

**すべてのコマンドに `--json` を付ける。** これは任意ではない。エージェントから
読めることが中核機能であり、後から追加するとなると、既に誰かがパースしている
出力を変えることになる。

## 3. TUI アクションの場合、命名に注意する

アクション名は利用者の設定ファイルに現れる。出荷した瞬間から公開 API になる。

```rust
enum Action { NextDay, PrevDay, Open, Search, Quit, /* ここに追加 */ }
```

- キーではなく意図で命名する。`NextDay` であって `PressL` ではない
- TOML では snake_case（`next_day`）。バリアント名と対応させる
- 該当する `Mode` の `resolve()` に追加する。描画・更新コードの中で
  `KeyEvent` を直接 match しない
- 既定のバインドは `Config::default()` に書く。他の場所には書かない
- そのモードで既定キーが既に使われていないか確認する。重複バインドは
  起動時エラーにする

## 4. 設定への露出

コマンドが設定を読むなら、該当セクションにフィールドを追加し、`#[serde(default)]`
を付ける。部分的な設定ファイルでも読み込めるようにするため。

追加後に確認すること: `pen config init` に新しいフィールドが出力されるか。
出ないなら、既定値が `impl Default` の外に書かれている。`config init` に
パッチを当てるのではなく、そちらを直すこと。

トップレベルに新しいフィールド(または `[keys.*]` のような新しいセクション)
を足したら、`src/config/mod.rs` の `render_default_config` にもそのフィールド
向けのコメント定数を足す。ここを忘れると、値は出力されるがコメントが無い
まま(壊れはしないが、初めて使う人への説明が抜ける)。

## 5. テスト

最低限これだけは書く。

- 引数のパース。特に厄介なケース — サブコマンド名に見えるテキスト、`-` で
  始まるテキスト、空入力
- 挙動そのもの。ディスクに触れるものは `tempfile` を使う。テストで `~/notes`
  を絶対に使わない
- `--json` 出力の形
- 画面に描画するものは、`east-asian-width` スキルにある幅のテスト

## 6. ドキュメント

- ヘルプテキスト — 完全な文で、専門用語を使わずに。多くの利用者が読むのはここだけ
- 利用者向けのコマンドなら `README.md` のコマンド一覧
- `docs/ROADMAP.md` — 予定セクションから該当項目を移す
- `docs/DESIGN.md` — 将来の読み手が覆したくなりそうな判断をした場合のみ

## 7. 仕上げ

```sh
cargo fmt
cargo clippy -- -D warnings
cargo test
```

## 忘れやすいこと

- 新しいコマンドへの `--json`
- 名前がメモ本文として自然な文字列と衝突している
- 既定値を `impl Default for Config` の外に二重に書いている
- 新しい設定フィールドを `render_default_config` のコメントに反映し忘れている
- アクションを意図ではなくキーで命名している
- ヘルプテキストを、既にツールを知っている人向けに書いている
